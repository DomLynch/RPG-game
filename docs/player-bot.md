# Local combat test player

Build once (`npm run build`), then run `node scripts/player-bot.mjs`. The default batch uses the charged strategy against Pitborn on Easy at three deterministic seeds derived from 731. Options: `--strategy=charged|counter`, `--opponent=pitborn`, `--opponents=all` (all playable opponents), `--seed=731`, `--fights=3` (maximum 12), `--reaction-ms=180` (100–700), `--step-ms=32`, `--no-video`, `--out=artifacts/combat/player-bot`. `--smoke` runs one fight. The counter strategy remains a diagnostic; its wall and post-dodge punish decisions are being tuned.

The controller uses the normal browser keyboard path. Charged mode approaches, charges Heavy, answers readable tells and recovers stamina. Counter mode approaches under directional guard, waits for a confirmed block, presses Heavy for the guard counter, and may stab after an opponent miss if within reach. It can read the local debug overlay's current gap, position, stamina and fighter phase, and the `frankendom:combat` event stream's current attack direction and block result. Direction changes wait the configured reaction delay. It has no future state, damage override or direct simulation control. A local-only `debug=1&botSeed=N` URL selects the starting seed; public hosts ignore it.

Each fight writes `opponent-seed.json` (all inputs and combat events with simulation ticks), optionally `opponent-seed.webm` (full fight plus five seconds of its conclusion, with a visible seed/tick label) and the compact batch `summary.json`. Match video frames to JSON events using the on-video tick label. All runs, including losses and timeouts, are retained. Receipts include thrust attempts/hits/damage, damage taken, missed player swings, estimated seconds near the wall (one-second position samples), seconds in contact-free stretches of at least five seconds, the longest contact gap, and the number of blocks/parries followed by a player hit before the next opponent hit within two seconds. These are diagnostic measures, not a gameplay score. Held keys are released in cleanup on wins, losses, timeouts and errors; a loss also verifies that Rematch starts with keys released. A new fight uses a fresh browser context. The script exits nonzero unless the batch wins at least 70% against each selected Easy opponent without runner errors.

These are mechanical test results. Debug observations are more precise than a human's, and the browser viewport emulates a phone. Footage and physical phone playtests remain the evidence for readability and control feel.
