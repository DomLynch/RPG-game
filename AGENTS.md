- **Character briefs specify OUTLINE, not build — Lead, 2026-09-22.** A new archetype's reference and silhouette work is specified by the character of its outline (hard armoured edges, broken fur, falling cloth, a one-heavy-side asymmetry), never by how big the figure is. Measured twice, independently, on the two reference sheets run that day: the Shieldmaiden's three candidates scored 0.24/0.28/0.24 on shoulder-width over figure-height with the Veteran at 0.29 — inside the candidates' own spread — and the Knight's three scored 0.39-0.40 against the Executioner's 0.36. Mass separated the candidates from each other by 0.04 and from the existing roster by nothing; the owner picked on outline both times. So a brief that describes a character as "big", "broad" or "heavier than X" has not specified anything a reskin check can fail. Two corollaries, each paid for in rework: an approved reference is an approved **direction, not a render** — generator artifacts in the chosen panel (half-open hands, stray flare) are never a specification, and nothing is authored from the PNG; and every character brief **names all six takeable pieces** (Helmet, Body, Arms, Gloves, Greaves, Boots) mapped to its reference, because nothing on the body is rig dressing (Dom, 2026-09-22). Naming is not authoring — the build order stays Recruit-2 first, and where the reference shows no piece for a slot, the brief says so and proposes rather than inventing. **A silhouette comparison measures the mask, not the backdrop.** A background check certifies only the backdrop: a pale or metallic fighter's skin, gloves or blade can sit brighter than any 8-bit backdrop, so a threshold cut punches holes through the mark itself (measured on the Nightborn, on an image whose background scored a perfect 0 on both gates: the beauty cut loses 5,056 px, 2.47 % of his mask, identical under a global and a per-row cut — and the beauty mask is a strict subset of the plate's, so the cut only ever loses the figure, never gains it). **Define both masks in one function before differencing them, and never erode a mask you are about to difference** — that figure moved twice before it settled, once because enclosed negative space (between the legs, inside a crown) was counted as lost figure, and once because `MinFilter(3)` was applied to one side of the difference only, so the erosion read as loss.). The reliable mask is an unlit-black plate rendered at the same camera, which cuts exactly with no threshold to get wrong — `scripts/character-preview.mjs --flat` (#500). Inspect the mask before using any beauty pass as a comparison, and never upscale one: normalising a short mask up to the comparison height invents edge detail the render never had, on one side of the pair only — that is a bias, not noise (a 236 px figure disagrees with its own 1,034 px render by 3.7 % IoU).
